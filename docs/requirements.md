# 查询与双智能体需求

状态：草案。业务范围来自 [需求说明.md](../需求说明.md)，查询与智能体分工来自 [流程.md](../流程.md)。第 8 节是本轮已确认的决定。本文只定义要做什么，不表示系统已经按本文实现。

## 1. 背景与目标

普通用户用自然语言查询已导入的金融资料。用户不需要知道文件放在哪里。系统检索知识库后给出有依据、可追溯的回答。

本轮要固定三条路径：

1. 闲聊：不查资料。
2. 简单查询：走一次共用私有库查询，直接回答。
3. 复杂任务：主 Agent 用 ReAct 编排，两个子 Agent 用 Self-Ask 取证，主 Agent 再组织回答。

私有库子 Agent 的每一步查询都执行和简单查询相同的共用过程。联网子 Agent 用百炼 MCP 回答自己的追问。两条路径都不另写一套问题理解。

系统是资料查询和解释工具。它不提供个性化投资建议，不承诺收益，不替代正式产品文件、监管文件或人工判断。来源：[需求说明.md](../需求说明.md) 第 1、7 节。

### 1.1 不在本轮范围

- 入库流水线本身（上传、解析、切片、向量化入库）保持现状，不在本文重做。
- [需求说明.md](../需求说明.md) 第 10 节的后续能力：产品筛选界面、净值行情、收藏、浏览历史、风险测评联动、个性化推荐、移动端、人工客服转接。个性化设置里只做长期记忆的增删改，不做推荐。
- 为某一家公司、某一个产品或某一个文件名写专用规则。文档和流程图里的具体名称只是例子。

## 2. 术语

| 术语 | 含义 | 限制 |
|---|---|---|
| 简单查询 | 意图识别后的一次共用查询 | 过程见 REQ-004，不经过主 Agent 循环 |
| 复杂任务 | 需要拆开取证的任务 | 只由主 Agent 编排 |
| 主 Agent | 面向用户的协调者 | 使用 ReAct，拆任务、检查结果、组织最终回答 |
| 私有库子 Agent | 查询已入库资料，并在同一次查询中检索网页摘要 | 使用 Self-Ask；查询步骤与简单查询相同 |
| 联网子 Agent | 专门检索外部网页 | 使用 Self-Ask；只调用百炼 MCP |
| 共用私有库查询 | 简单查询和私有库子 Agent 共用的检索过程 | 见 REQ-004 |
| 会话记忆 | 当前对话里已经确认的主体、期间和话题 | 随用户输入一起交给意图识别和查询 |
| 长期记忆 | 用户明确要求记住，或在个性化中写上的内容 | 不从普通对话自动归纳 |
| 注册表 | 主体规范名、简称和歧义关系 | 向量对不上时做最长匹配 |
| 示例 | 用来说明规则的公司、产品或文件 | 不是系统只处理这些对象的证据 |

## 3. 功能需求

### REQ-001 接收问题

- 触发：用户在已有对话中提交一条问题。
- 输入：当前问题；该对话最近十条消息；该对话已保存的会话记忆；该用户已保存的长期记忆。
- 处理：空问题不进入检索。问题最长 4000 字，与现有 `ChatService.send` 一致。
- 输出：进入 REQ-002。
- 来源：[流程.md](../流程.md) 第 1 步。最近十条是目标。现有确认节点默认读取更多历史，落地时对齐，不改变已保存的完整历史。

### REQ-002 意图识别

- 触发：REQ-001 完成。
- 处理：必须调用 LLM 做分类。不得用关键词表或正则代替这次调用。模型只输出三类之一：闲聊、简单查询、复杂任务。
- 交给模型的执行标准：
  - 闲聊：寒暄、感谢，或回答不需要资料的交谈。
  - 简单查询：一个问题用一次共用私有库查询就能回答，包括单个产品、概念、公告、政策或业务规则。
  - 复杂任务：需要拆成多个子问题、比较多个主体，或后一步依赖前一步的结果。
- 分流看要完成的工作，不按问题长短或出现了几个名称决定。
- 输出无法解析时，再调用一次。仍然无法解析则停止检索，提示分类失败，不猜一条路径。
- 输出：闲聊 → REQ-003；简单查询 → REQ-004；复杂任务 → REQ-007。

### REQ-003 闲聊

- 触发：意图为闲聊。
- 处理：不查询私有库，不联网，不提取产品名。
- 输出：直接回答，并保留对话记录。闲聊不强制附带资料来源。

### REQ-004 共用私有库查询

简单查询执行一次本过程并直接回答。私有库子 Agent 的主问题和每个 Self-Ask 追问都执行同一次过程，见 REQ-008。

1. 结合最近十条消息、会话记忆和长期记忆改写问题。代词要落到已经确认的主体上。长期记忆只作为用户偏好和已知事实，不能扩大检索权限。
2. 从改写后的问题提取要查询的产品或主体名称，可以多个。
3. 没有提取到名称时，跳过名称索引和同名过滤，用改写后的问题直接检索资料块。概念、公告、政策和业务规则问题按这一支处理。
4. 提取到名称时，用 BGE-M3 对每个名称做稠密、稀疏双向量检索。按 REQ-005 确认名称。用户尚未确认时停在这里，不检索正文。向量对不上时按 REQ-006 处理。
5. 名称确定后，用改写后的问题，只在同名资料块中做普通检索。无名称的问题不做这一过滤。
6. 用 HyDE 生成假设性检索文本，再检索一次。有名称时仍只查同名资料块。假设文本只用于检索，不能当作事实写进回答。
7. 用户打开联网搜索时，用百炼 MCP 检索改写后的问题，取得网页标题、链接和摘要。用户关闭时不调用百炼。
8. 把普通检索、HyDE 检索和已取得的网页摘要放进同一次 RRF 排序。网页摘要使用返回顺序作为名次。关闭联网时只融合前两路。
9. 简单查询把排序结果交给模型生成回答，并满足 REQ-010。私有库子 Agent 把排序结果、链接、缺项和状态交回主 Agent，不生成给用户的最终回答。

联网失败时保留已经检索到的私有库结果，RRF 只融合普通检索和 HyDE，并说明联网不可用。

### REQ-005 名称匹配与用户确认

对每个提取出的名称，取双向量检索的最高分：

| 分数 | 行为 |
|---|---|
| 大于或等于 0.9 | 直接采用匹配到的规范名称，可同时采用多个。等于 0.9 也直接采用 |
| 大于或等于 0.6，且小于 0.9 | 交给用户确认；多个候选时可以多选 |
| 低于 0.6 | 视为向量未匹配，进入 REQ-006 |

确认之前不得检索该名称的正文，也不得由模型替用户选定。

用户拒绝确认，或候选都不选：该名称不进入正文检索。若因此没有任何可查名称，按 REQ-010 说明未检索到足够信息。

### REQ-006 注册表最长匹配

- 触发：向量匹配未得到可直接采用或待确认的名称。
- 处理：在注册表中按规范名做最长匹配，短名不能截走已经被更长名称占用的文字。匹配后，若仍有简称对应两个及以上主体，且上下文没有消解，必须询问用户。
- 输出：确定的主体、待用户选择的歧义，或明确的未识别。
- 约束：某个简称同时指向多家机构，只说明歧义要问用户。该简称不是系统的业务范围。

### REQ-007 主 Agent：ReAct

- 触发：意图为复杂任务。
- 框架：主 Agent 使用 ReAct。每一步先判断当前证据是否够回答，再执行一个动作，再读取该动作的结果。允许的动作只有：
  - 派发私有库子任务
  - 派发联网子任务
  - 把名称确认交给用户并暂停
  - 结束并组织回答
- 处理：子任务指定查询类型。有依赖时，依赖完成后再派发下游。互不依赖的子任务可以并行。
- 停止：
  - 证据已经够回答，或只能明确写出缺口。
  - 补查最多两轮。补查只为缺口或冲突派发，不重复已经成功的子任务。初始拆分不算补查。
  - 一次用户问题产生的子任务总数小于 5，含初始拆分和两轮补查。达到 4 个后不再派发。
- 达到轮次或数量上限时，用已有证据回答，并写明未完成的缺口。
- 约束：子 Agent 不能再创建子 Agent，不能改知识库，不能写长期记忆，不能直接向用户发布最终回答。

### REQ-008 子 Agent：Self-Ask

两个子 Agent 都使用 Self-Ask。接到一个子任务后，可以提出追问；每个追问必须先检索再记录中间结果；追问结束后把证据包交回主 Agent。

- 每个子任务最多两个追问。追问占用的是该子任务内部的步骤，不另占主 Agent 的子任务名额。
- 私有库子 Agent 的主问题和追问都执行 REQ-004 的第 1–8 步。
- 联网子 Agent 的主问题和追问都调用百炼 MCP，返回标题、摘要和链接。它不跑名称索引，也不把网页结果写成私有库事实。
- 名称落入 REQ-005 的待确认区间时，子 Agent 停下来，由主 Agent 把确认问题交给用户。用户确认后从停住的步骤继续，不重新猜测名称。
- 中间追问的结论必须带各自的来源。没有来源的中间结论不能进入证据包。

### REQ-009 主 Agent 检查并回答

- 触发：本轮子 Agent 都已返回，或因确认、失败而停下。
- 处理：按子任务检查三类结果，三者必须分开，不能互相改写：
  - 有资料支持
  - 库内或网页没有足够资料
  - 检索或模型调用失败
- 未满足、补查未满两轮、且子任务总数仍小于 5：回到 REQ-007，只为缺口或冲突派发新任务。
- 已满足，或不能再补查：主 Agent 组织最终回答。优化不能新增资料来源，不能把缺口填成数字。

### REQ-010 回答必须带来源

除闲聊和下面两种固定说明外，给用户的回答必须附带来源。

- 私有库来源至少包含资料里已经有的这些字段：资料名称、内容类型、产品名称或产品代码、发布时间、来源文件名。没有的字段不编造。
- 网页来源必须同时有标题和可打开的链接。只有摘要、没有链接的网页结果不能当作来源。
- 回答正文用 `[n]` 标出引用。引用列表写出对应资料；私有库资料附带下载链接，网页附带地址。
- 没有足够资料时，说明当前知识库未检索到足够信息，并建议查看正式文件或咨询工作人员。这条说明本身不编造来源。
- 检索失败与“库里没有”使用不同说法。失败说明不编造来源。
- 不得编造数据、公告、产品条款或市场结论。回答里的事实必须能在所附来源中找到。

### REQ-011 资料范围

可查询的已导入资料包括：产品资料与说明书、基金招募说明书、基金产品资料概要、理财产品说明书、风险揭示书、市场资讯、行业分析、公司公告摘要、政策解读、术语、FAQ、业务流程。字段建议见 [需求说明.md](../需求说明.md) 第 5 节。

用户可以问产品事实、金融概念、已入库资讯、公告摘要、风险提示和业务规则。具体问法是例子，不是题型白名单。

### REQ-012 合规

- 不指示买入、卖出、持有或赎回。
- 不使用“一定赚钱、保证收益、保本无风险、稳赚不赔、一定会上涨、现在必须买入”这类承诺。
- 涉及收益、风险或决策时说明：金融产品有风险，历史业绩不代表未来，需结合自身承受能力，正式信息以合同、招募说明书、公告和监管文件为准。
- 资料可能滞后。问题依赖最新行情、净值、公告或价格时，提示查看官方或实时来源。实时数据接入不在本轮范围。网页结果也不能被说成实时行情。

### REQ-013 对话交互

支持单轮问答、多轮追问、流式输出、历史记录、引用来源、重新提问和异常提示。追问沿用会话记忆中的主体，直到用户更换主体或出现新的歧义。

导入失败不影响已经运行的查询服务。该条沿用 [需求说明.md](../需求说明.md) 第 9 节，本轮不改变入库实现。

### REQ-014 长期记忆

- 只保存两类内容：用户在对话中明确要求记住的内容；用户在个性化设置中写入的内容。
- 普通问答、检索资料和模型回答不能自动写入长期记忆。
- 用户可以在个性化设置中查看、修改和删除。删除后，后续查询不再附带该内容。
- 长期记忆按用户保存，不按某一条对话保存。它和会话记忆分开。

## 4. 业务边界

| 情形 | 结果 |
|---|---|
| 空问题、超长问题 | 拒绝进入检索，提示原因 |
| 闲聊 | 不查库、不联网 |
| 意图输出两次都无法解析 | 提示分类失败，不检索 |
| 分数等于 0.9 | 直接采用 |
| 分数在 0.6 与 0.9 之间 | 暂停，等待用户；不把第一名当成已确认 |
| 用户多选 | 每个选中名称各自检索同名资料块 |
| 用户否认唯一候选 | 不检索该名称 |
| 短名对应多个主体 | 询问用户，不默认取其中一家 |
| 问题中没有产品或主体名称 | 跳过名称索引，直接检索资料块，并与 HyDE、网页摘要一起 RRF |
| 子 Agent 中途需要确认 | 整次复杂任务暂停，确认后继续原任务 |
| 子任务已经有 4 个 | 不再派发第 5 个 |
| 已经补查两轮 | 停止补查，用已有证据回答 |
| 一个子任务已有两个追问 | Self-Ask 停止，交回已有证据和缺项 |
| 只有一方资料 | 回答已有部分，并写明缺口和来源 |
| 两条资料冲突 | 并列两处来源，不取平均，不选一个当成唯一事实 |
| 私有库失败、联网成功 | 说明私有库失败；联网内容单独标链接 |
| 联网失败、私有库成功 | 用私有库回答，附带私有库来源，并说明联网不可用 |
| 两者都没有资料 | REQ-010 的无资料说明 |
| 两者都调用失败 | 说明失败，不说成“知识库没有该资料” |
| 回答使用了网页内容但没有链接 | 该网页内容不能出现在最终回答里 |
| 用户说“记住这一点” | 写入长期记忆 |
| 用户只是在提问 | 不写入长期记忆 |

## 5. 非功能需求

| 项 | 要求 |
|---|---|
| 准确与追溯 | 产品条款、财务数字、公告内容和网页结论都要回到所附来源 |
| 隔离 | 每个子任务使用自己的查询状态和输出目录，不能写乱另一个任务的检索结果 |
| 可观测 | 记录意图、ReAct 的判断、动作和观察、Self-Ask 追问、名称决策、检索状态和补查轮次。不记录密钥 |
| 性能阈值 | 待确认。现有资料没有简单查询或复杂任务的时限 |
| 安全 | 不回答索取密钥、内部配置或原始检索块的请求；沿用现有拒绝口径 |

## 6. 验收标准

### AC-001 三类分流（REQ-002、REQ-003、REQ-004、REQ-007）

- 给定一句问候，且模型返回闲聊。预期：不出现名称确认、私有库检索或联网调用。
- 给定一个单主体资料问题，且模型返回简单查询。预期：走一次 REQ-004，主 Agent 不拆子任务。
- 给定模型返回复杂任务。预期：主 Agent 按 ReAct 派发子任务，用户最终只看到主 Agent 的回答。
- 给定分类接口未被调用。预期：不能完成分流。关键词命中不能代替这次 LLM 调用。

### AC-002 名称分数（REQ-005）

- 给定最高分大于 0.9。预期：直接采用，不询问。
- 给定最高分等于 0.9。预期：直接采用，不询问。
- 给定最高分在 0.6 与 0.9 之间，且有两个候选。预期：列出候选，允许多选；用户选择前没有正文检索。
- 给定最高分低于 0.6。预期：不把该命中当确认结果，转入注册表。
- 给定一个需求说明示例以外的产品名，分数规则相同。

### AC-003 最长匹配与歧义（REQ-006）

- 给定文本同时含有长规范名和它的短名。预期：长名占住对应文字，短名不重复截取。
- 给定一个未出现在示例里的简称，注册表中对应两个主体，上下文没有消解。预期：询问用户，不默认其中任何一个。

### AC-004 共用查询（REQ-004、REQ-008）

- 给定同一个已确认名称和同一个改写问题。操作：分别走简单查询和私有库子 Agent。预期：名称过滤、HyDE、百炼检索和三路 RRF 一致；子 Agent 不生成最终用户回答。
- 给定一个没有产品名的概念问题。预期：不查询名称索引，直接检索资料块。
- 给定普通检索、HyDE 和一条网页摘要。预期：三路进入同一次 RRF；摘要所在网页的链接留在结果里。
- 给定 HyDE 文本里出现一个资料中没有的数字。预期：该数字不进入回答事实。

### AC-005 失败、冲突、来源与上限（REQ-008、REQ-009、REQ-010）

- 给定私有库有资料、联网调用抛错。预期：回答使用私有库并附带来源，同时说明联网不可用。
- 给定检索组件连接失败。预期：提示失败，不用“未检索到足够信息”代替。
- 给定两份资料对同一事实给出不同数值。预期：两处都引用，不合并成一个数。
- 给定最终回答引用了网页摘要。预期：同一处附带该网页链接。没有链接时，这段摘要不出现。
- 给定已派发 4 个子任务且仍有缺口。预期：不派发第 5 个，回答写明缺口。
- 给定已经补查两轮。预期：不再开始第三轮补查。

### AC-006 合规、追问与长期记忆（REQ-012、REQ-013、REQ-014）

- 给定“我该不该现在买入这个产品”。预期：不给出买卖指令，保留风险提示和已有来源。
- 给定上一轮已确认主体后，用户用“它”追问赎回规则。预期：沿用该主体，不重新要求选择，除非出现新的歧义。
- 给定用户说“记住我只看稳健型产品”。预期：写入长期记忆，后续查询能读到。
- 给定用户只提问、没有要求记住。预期：不新增长期记忆。

### AC-007 两种框架（REQ-007、REQ-008）

- 给定一个复杂任务。预期：主 Agent 的记录里能看到判断、动作和观察；动作只来自 REQ-007 的四种。
- 给定私有库子任务需要一个中间问题。预期：子 Agent 用 Self-Ask 提出追问，并用共用查询取得证据；追问不超过两个。
- 给定联网子任务。预期：追问只调用百炼 MCP，证据含链接，不生成用户回答。
