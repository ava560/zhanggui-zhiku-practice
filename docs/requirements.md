# 查询与双智能体需求

状态：草案。业务范围来自 [需求说明.md](../需求说明.md)，查询与智能体分工来自 [流程.md](../流程.md)。第 8 节是已确认的决定，第 9 节是尚未确认、会影响实现的事项。本文只定义要做什么，不表示系统已经按本文实现。

## 1. 背景与目标

普通用户用自然语言查询已导入的金融资料。用户不需要知道文件放在哪里。系统检索知识库后给出有依据、可追溯的回答。

本轮要固定三条路径：

1. 闲聊：不查资料。
2. 简单查询：走一次共用私有库查询，直接回答。
3. 复杂任务：主 Agent 用 ReAct 编排，两个子 Agent 用 Self-Ask 取证，主 Agent 再组织回答。

私有库子 Agent 和简单查询复用同一套问题理解，并分别调用表数据检索工具与文档 RAG 工具；问题同时涉及两类证据时可以调用两者。联网子 Agent 用百炼 MCP 回答自己的追问。

在这三条路径之外，增加四类能力：

1. 结构化数据：PostgreSQL 用四张元数据表登记文件、业务表、字段和指标，并把表格文件的行写入该文件自己的业务表。查询只使用当前可查询版本。业务人员提出需求后，模型依据元数据和相关表数据查找，或给出这些数据能够支持的结果。
2. 数据更新：对话页左侧可以设置每日定时任务。任务按其 SOP，运行已经指定的代码，更新对应的表数据。
3. 数据血缘：大模型或定时任务保存下来的加工数据，可以倒查它用了哪些基础数据、经过哪些加工步骤、由哪段已登记代码完成。血缘记录保存在 MongoDB。
4. 用户技能：用户可以保存自己的技能。问题里用 `@` 点名已保存技能，或本轮检索到的任务已经绑定该技能时，模型按该技能的做法处理本轮问题。

系统是资料查询和解释工具。它不提供个性化投资建议，不承诺收益，不替代正式产品文件、监管文件或人工判断。来源：[需求说明.md](../需求说明.md) 第 1、7 节。结构化数据、定时更新、血缘和技能的来源见第 7 节。

### 1.1 不在本轮范围

- 原有 PDF、Markdown、Word 的切片、向量化路径保持；新增表格文件（xlsx、xlsm、xls、csv）的原件留存、元数据确认、表数据入库及检索索引路径。每日定时任务不代替文件上传。
- 对话不改为只查 PostgreSQL。文档资料仍走原有查询；只有元数据能够对应上的需求才读取表数据。
- [需求说明.md](../需求说明.md) 第 10 节的后续能力：产品筛选界面、净值行情、收藏、浏览历史、风险测评联动、个性化推荐、移动端、人工客服转接。个性化设置里只做长期记忆的增删改，不做推荐。
- 为某一家公司、某一个产品或某一个文件名写专用规则。文档和流程图里的具体名称只是例子。
- 在对话里执行任意命令或脚本，以及把查询结果自动写成投资指令。定时任务可以运行已登记函数，或人员已确认的另附 `.py`。
- 把业务行、字段说明或对话原文复制进 MongoDB 充当血缘。血缘只记版本、步骤和代码标识。
- 行级血缘。全体用户从对话页左上角按数据版本倒查，不另做一套血缘库。

## 2. 术语

| 术语 | 含义 | 限制 |
|---|---|---|
| 简单查询 | 意图识别后的一次共用查询 | 过程见 REQ-004，不经过主 Agent 循环 |
| 复杂任务 | 需要拆开取证的任务 | 只由主 Agent 编排 |
| 主 Agent | 面向用户的协调者 | 使用 ReAct，拆任务、检查结果、组织最终回答 |
| 私有库子 Agent | 按问题调用表数据工具、文档 RAG 工具或两者，返回证据 | 使用 Self-Ask；不向用户直接回答 |
| 联网子 Agent | 专门检索外部网页 | 使用 Self-Ask；只调用百炼 MCP |
| 共用文档 RAG 查询 | 简单查询和私有库子 Agent 共用的资料块检索过程 | 见 REQ-004；表格数据由 REQ-016 的独立工具查询 |
| 会话记忆 | 当前对话里已经确认的主体、期间和话题 | 随用户输入一起交给意图识别和查询 |
| 长期记忆 | 用户明确要求记住，或在个性化中写上的内容 | 不从普通对话自动归纳 |
| 注册表 | 主体规范名、简称和歧义关系 | 向量对不上时做最长匹配 |
| 示例 | 用来说明规则的公司、产品或文件 | 不是系统只处理这些对象的证据 |
| 文件元数据 | 一个已登记文件在 PostgreSQL 中的文件、表、字段及指标定义 | 按导入版本留存；只有当前版本参与查询，字段说明不是数据值 |
| 文件数据表 | 存放该文件表格数据的 PostgreSQL 表 | 表名来自该文件的元数据 |
| 字段角色 | 维度、度量、时间、主键、属性之一 | 只有度量可以作为 SUM 或 AVG 的目标；属性只描述、不相加 |
| 定时任务 | 左侧设置的每日数据更新任务 | 绑定一份 SOP 和一段已指定代码；不是文档上传任务 |
| SOP | 用户写在这条定时任务上的更新说明 | 说明要维护哪些数据、按什么规则更新 |
| 基础数据 | 加工所读取的、已经存在的文件版本和表数据版本 | 字段说明、未保存的查询结果和对话原文不是基础数据 |
| 加工数据 | 由大模型加工步骤或定时任务新保存的数据版本 | 只生成回答或字段说明、没有新数据版本时，不是加工数据 |
| 数据血缘 | 一条加工数据指向基础数据、加工步骤和代码标识的记录 | 只说明来历，不代替 REQ-010 的回答引用，也不参与检索 |
| 技能 | 用户编写的一套工作方法 | 包含名称、何时使用，以及模型要按顺序执行的步骤。它教模型完成一类工作 |

## 3. 功能需求

### REQ-001 接收问题

- 触发：用户在已有对话中提交一条问题。
- 输入：当前问题；该对话最近十条消息；该对话已保存的会话记忆；该用户已保存的长期记忆。
- 处理：空问题不进入检索。问题最长 4000 字，与现有 `ChatService.send` 一致。
- 输出：进入 REQ-002。
- 来源：[流程.md](../流程.md) 第 1 步。最近十条是目标。现有确认节点默认读取更多历史，落地时对齐，不改变已保存的完整历史。

### REQ-002 意图识别

- 触发：REQ-001 完成。
- 处理：必须调用 LLM 做分类。不得用关键词表或正则代替这次调用。模型只输出三类之一：闲聊、简单查询、复杂任务。
- 交给模型的执行标准：
  - 闲聊：寒暄、感谢，或回答不需要资料的交谈。
  - 简单查询：一个问题用一次私有库取证就能回答；可调用文档 RAG 工具、表数据工具或两者，包括单个产品、概念、公告、政策、业务规则或单表查数。
  - 复杂任务：需要拆成多个子问题、比较多个主体，或后一步依赖前一步的结果。
- 分流看要完成的工作，不按问题长短或出现了几个名称决定。
- 输出无法解析时，再调用一次。仍然无法解析则停止检索，提示分类失败，不猜一条路径。
- 输出：闲聊 → REQ-003；简单查询 → REQ-004；复杂任务 → REQ-007。

### REQ-003 闲聊

- 触发：意图为闲聊。
- 处理：不查询私有库，不联网，不提取产品名。
- 输出：直接回答，并保留对话记录。闲聊不强制附带资料来源。

### REQ-004 共用文档 RAG 查询

简单查询需要文档证据时执行本过程并直接回答；私有库子 Agent 的主问题和 Self-Ask 追问需要文档证据时也复用本过程，见 REQ-008。表格数据走 REQ-016 的独立工具，不进入本节 RRF。

1. 结合最近十条消息、会话记忆和长期记忆改写问题。代词要落到已经确认的主体上。长期记忆只作为用户偏好和已知事实，不能扩大检索权限。
2. 从改写后的问题提取要查询的产品或主体名称，可以多个。
3. 没有提取到名称时，跳过名称索引和同名过滤，用改写后的问题直接检索资料块。概念、公告、政策和业务规则问题按这一支处理。
4. 提取到名称时，用 BGE-M3 对每个名称做稠密、稀疏双向量检索。按 REQ-005 确认名称。用户尚未确认时停在这里，不检索正文。向量对不上时按 REQ-006 处理。
5. 名称确定后，用改写后的问题，只在同名资料块中做普通检索。无名称的问题不做这一过滤。
6. 用 HyDE 生成假设性检索文本，再检索一次。有名称时仍只查同名资料块。假设文本只用于检索，不能当作事实写进回答。
7. 用户打开联网搜索时，用百炼 MCP 检索改写后的问题，取得网页标题、链接和摘要。用户关闭时不调用百炼。
8. 把普通检索、HyDE 检索和已取得的网页摘要放进同一次 RRF 排序。网页摘要使用返回顺序作为名次。关闭联网时只融合前两路。
9. 简单查询把排序结果交给模型生成回答，并满足 REQ-010。私有库子 Agent 把排序结果、链接、缺项和状态交回主 Agent，不生成给用户的最终回答。

联网失败时保留已经检索到的私有库结果，RRF 只融合普通检索和 HyDE，并说明联网不可用。

### REQ-005 名称匹配与用户确认

对每个提取出的名称，取双向量检索的最高分：

| 分数 | 行为 |
|---|---|
| 大于或等于 0.9 | 直接采用匹配到的规范名称，可同时采用多个。等于 0.9 也直接采用 |
| 大于或等于 0.6，且小于 0.9 | 交给用户确认；多个候选时可以多选 |
| 低于 0.6 | 视为向量未匹配，进入 REQ-006 |

确认之前不得检索该名称的正文，也不得由模型替用户选定。

用户拒绝确认，或候选都不选：该名称不进入正文检索。若因此没有任何可查名称，按 REQ-010 说明未检索到足够信息。

### REQ-006 注册表最长匹配

- 触发：向量匹配未得到可直接采用或待确认的名称。
- 处理：在注册表中按规范名做最长匹配，短名不能截走已经被更长名称占用的文字。匹配后，若仍有简称对应两个及以上主体，且上下文没有消解，必须询问用户。
- 输出：确定的主体、待用户选择的歧义，或明确的未识别。
- 约束：某个简称同时指向多家机构，只说明歧义要问用户。该简称不是系统的业务范围。

### REQ-007 主 Agent：ReAct

- 触发：意图为复杂任务。
- 框架：主 Agent 使用 ReAct。每一步先判断当前证据是否够回答，再执行一个动作，再读取该动作的结果。允许的动作只有：
  - 派发私有库子任务
  - 派发联网子任务
  - 把名称确认交给用户并暂停
  - 结束并组织回答
- 处理：子任务指定查询类型。有依赖时，依赖完成后再派发下游。互不依赖的子任务可以并行。
- 停止：
  - 证据已经够回答，或只能明确写出缺口。
  - 补查最多两轮。补查只为缺口或冲突派发，不重复已经成功的子任务。初始拆分不算补查。
  - 一次用户问题产生的子任务总数小于 5，含初始拆分和两轮补查。达到 4 个后不再派发。
- 达到轮次或数量上限时，用已有证据回答，并写明未完成的缺口。
- 约束：子 Agent 不能再创建子 Agent，不能改知识库，不能写长期记忆，不能直接向用户发布最终回答。

### REQ-008 子 Agent：Self-Ask

两个子 Agent 都使用 Self-Ask。接到一个子任务后，可以提出追问；每个追问必须先检索再记录中间结果；追问结束后把证据包交回主 Agent。

- 每个子任务最多两个追问。追问占用的是该子任务内部的步骤，不另占主 Agent 的子任务名额。
- 私有库子 Agent 的主问题和追问按需调用 REQ-004 文档工具、REQ-016 表数据工具或两者；调用文档工具时执行 REQ-004 的第 1–8 步。两种工具的证据分别标明来源，不能把表格行伪装成资料块。
- 联网子 Agent 的主问题和追问都调用百炼 MCP，返回标题、摘要和链接。它不跑名称索引，也不把网页结果写成私有库事实。
- 名称落入 REQ-005 的待确认区间时，子 Agent 停下来，由主 Agent 把确认问题交给用户。用户确认后从停住的步骤继续，不重新猜测名称。
- 中间追问的结论必须带各自的来源。没有来源的中间结论不能进入证据包。

### REQ-009 主 Agent 检查并回答

- 触发：本轮子 Agent 都已返回，或因确认、失败而停下。
- 处理：按子任务检查三类结果，三者必须分开，不能互相改写：
  - 有资料支持
  - 库内或网页没有足够资料
  - 检索或模型调用失败
- 未满足、补查未满两轮、且子任务总数仍小于 5：回到 REQ-007，只为缺口或冲突派发新任务。
- 已满足，或不能再补查：主 Agent 组织最终回答。优化不能新增资料来源，不能把缺口填成数字。

### REQ-010 回答必须带来源

除闲聊和下面两种固定说明外，给用户的回答必须附带来源。

- 私有库来源至少包含资料里已经有的这些字段：资料名称、内容类型、产品名称或产品代码、发布时间、来源文件名。没有的字段不编造。
- 网页来源必须同时有标题和可打开的链接。只有摘要、没有链接的网页结果不能当作来源。
- 回答正文用 `[n]` 标出引用。引用列表写出对应资料；私有库资料附带下载链接，网页附带地址。
- 没有足够资料时，说明当前知识库未检索到足够信息，并建议查看正式文件或咨询工作人员。这条说明本身不编造来源。
- 检索失败与“库里没有”使用不同说法。失败说明不编造来源。
- 不得编造数据、公告、产品条款或市场结论。回答里的事实必须能在所附来源中找到。

### REQ-011 资料范围

可查询的已导入资料包括：产品资料与说明书、基金招募说明书、基金产品资料概要、理财产品说明书、风险揭示书、市场资讯、行业分析、公司公告摘要、政策解读、术语、FAQ、业务流程。字段建议见 [需求说明.md](../需求说明.md) 第 5 节。

用户可以问产品事实、金融概念、已入库资讯、公告摘要、风险提示和业务规则。具体问法是例子，不是题型白名单。

### REQ-012 合规

- 不指示买入、卖出、持有或赎回。
- 不使用“一定赚钱、保证收益、保本无风险、稳赚不赔、一定会上涨、现在必须买入”这类承诺。
- 涉及收益、风险或决策时说明：金融产品有风险，历史业绩不代表未来，需结合自身承受能力，正式信息以合同、招募说明书、公告和监管文件为准。
- 资料可能滞后。问题依赖最新行情、净值、公告或价格时，提示查看官方或实时来源。实时数据接入不在本轮范围。网页结果也不能被说成实时行情。

### REQ-013 对话交互

支持单轮问答、多轮追问、流式输出、历史记录、引用来源、重新提问和异常提示。追问沿用会话记忆中的主体，直到用户更换主体或出现新的歧义。

导入失败不影响已经运行的查询服务。该条沿用 [需求说明.md](../需求说明.md) 第 9 节，本轮不改变入库实现。

### REQ-014 长期记忆

- 只保存两类内容：用户在对话中明确要求记住的内容；用户在个性化设置中写入的内容。
- 普通问答、检索资料和模型回答不能自动写入长期记忆。
- 用户可以在个性化设置中查看、修改和删除。删除后，后续查询不再附带该内容。
- 长期记忆按用户保存，不按某一条对话保存。它和会话记忆分开。

### REQ-015 文件与表元数据

- 所有导入文件都在 PostgreSQL 的 `doc_info` 登记文件名、格式、简介、上传任务、MinIO 原件对象键和版本。PDF、Word、Markdown 不因此自动产生业务数据表。
- 表格文件指 xlsx、xlsm、xls 和 csv。首版必须选定一个工作表或等效表；一份文件对应一张业务数据表。PostgreSQL 的 `table_info` 保存唯一物理表名、事实表或维度表角色、业务简介和字段清单快照；`column_info` 逐字段保存真实列名、类型、业务角色、别名和说明；`metric_info` 保存已登记指标及关联字段和计算口径。这四张是元数据表，业务数据表另计。
- `doc_info` 只保留上传任务标识。每日定时任务不写在这张表上，由任务记录引用文件的 `doc_id`。
- 导入时程序解析并初判物理类型，模型草拟简介、字段说明和别名，先写入 PostgreSQL 的 `pending` 元数据版本并标记生成来源；入库发布前由人员检查并确认表的事实/维度角色、字段类型与业务角色、说明及别名。无法确认的内容不得作为已核准元数据使用。
- `table_info` 的字段清单和 `doc_info` 的表格字段说明按版本从 `column_info` 生成，仅供展示；选表、校验和查询以当前可查询版本的 `column_info` 和业务表结构为准。
- `doc_id` 标识同一份逻辑文件，`import_version_id` 标识不同内容、工作表、导入配置或经明确修改的元数据版本，`data_version_id` 标识一次数据装载。不同版本的原件、元数据和数据行均保留；每份文件同时只有一个可查询导入版本及其当前数据版本。同一逻辑文件的原件字节、所选工作表和导入配置完全相同的重复上传直接复用已有版本，只清理本次重复的临时上传；明确修改元数据须另建版本。
- 字段说明只解释字段含义，不能被当作这个字段里已经存在的数值、日期或名单。规则适用于所有文件，不能把示例文件当成其他文件的模板。

### REQ-016 表数据入库，并据此查找或完成需求

- 触发：文件已经有 REQ-015 的元数据；业务人员用自然语言提出查找或数据处理需求。
- 入库：表格文件的行按已确认的字段写入指定业务表；字段与 `column_info` 不一致时本次不入库，旧版及当前可查询版本均保持不变。原件上传 MinIO；已确认元数据另建 Milvus 元数据集合，文档切片保留原集合。
- 值索引：`column_info.value_index` 是否开启由人员在导入时检查确认；只把选定字段的实际取值及字段/表/版本定位信息写入 Elasticsearch。新版本索引完成并校验后才切换可查询版本，旧版索引在切换后清理；保留旧版原件、元数据和行数据。
- 指标：`metric_info` 的可执行公式保存为受限结构，仅引用同一张表的已登记字段；首版允许 `SUM`、`COUNT`、`COUNT(DISTINCT ...)`、`AVG` 和加减乘除，须验证字段类型和除零情况。`SUM` 和 `AVG` 的目标字段角色必须是度量。分组和过滤属于这一次查询计划，不写进指标公式。候选指标可以留 `draft` 而不阻塞已确认字段的数据入库；自由文本公式及未经确认的指标不参与计算，不自动跨表关联。
- 查询：表数据工具先召回候选字段、指标和实际值，再读取当前可查询版本的完整元数据，只查询其登记的业务表；文档 RAG 工具沿用原资料块检索。两个工具只返回分类型、带来源的证据，由 Agent 决定是否需要同时调用。
- 输出有两种，必须能分清：
  - 数据查找：返回表中能够对上的记录或由这些记录直接汇总的结果。
  - 需求完成：需求可以完全由相关表数据得出时，返回这个结果。
- 来源：结果附带来源文件名、表名和用到的字段，并沿用 REQ-010 的引用方式。没有查到记录时说明没有对应数据，不编造来源。
- 约束：
  - 元数据没有列出的表或字段不参与查询。
  - 文件与业务主键、文件与文件之间的关联，只有导入时由人员明示确认的才可以使用。没有写下的关联不查询，系统不另造业务主键。本轮不新增关联表。未写明关联时，只返回各自能确定的部分。
  - 表工具的无记录、查询失败、指标尚未确认分别说明；文档数字或字段说明不能填补该表没有查到的数值。
  - 字段定义发生变化时，不自动删列，也不自动给旧行填值。旧的可查询版本保持不变，由人决定怎么迁移。人处理完成前，不把未迁移的新结构发布成可查询版本。
  - 只读提问把结果返回用户，不写回表。用户要求把本次结果写回已登记表时可以写入；写入必须与已确认字段一致，生成新的数据版本，并先完成 REQ-018 的血缘。写回由数据处理完成，不在对话回答过程中执行脚本。
  - 数据库连接失败时说明查询失败。这个说明和“表中没有记录”分开。
  - 由表格数据做成的回答仍遵守 REQ-012。

### REQ-017 左侧每日定时任务

- 触发：用户在对话页左侧设置定时任务。
- 输入：一份 SOP、这段 SOP 所指定的更新代码、所涉文件的 `doc_id`，以及每天运行一次的安排。任务不在 `doc_info` 上维护任务名称列表。
- 处理：时区固定为北京时间。钟点和 SOP 由用户在这条任务上填写。两项都已填写、任务已启用，并且有可运行代码时，到北京时间的钟点自动运行，每天最多成功一次。错过计划时刻不补跑。缺钟点、缺 SOP 或没有可运行代码的那一条不运行。更新仍要满足 REQ-016 的字段一致要求，并受 REQ-020 的 30 分钟上限约束。
- 可以同时启用多条任务。全体用户都可以创建、修改和停用。停用后不再自动运行，任务记录和表数据都保留。
- 只追加业务行时，表结构和字段定义不变，不改写已经回答的对话，也不刷新文档切片向量和图。度量、时间等未开启 `value_index` 的列多了一行，不重建值索引。已开启 `value_index` 的字段出现新的取值时，只把这个新取值补进 ES。补齐并与 REQ-018 的血缘都完成后，才切换可查询版本。失败时旧版本仍可查询。
- 输出：左侧能看到该任务、所绑定的 SOP、所指定的代码，以及最近一次是成功、失败还是尚未运行。
- 约束：
  - 定时任务不是现有的文档上传任务。上传、解析和向量化保持原样。
  - 任务代码可以是项目里已登记的更新函数，或用户另附的 `.py`。另附脚本先进入待确认版本；人员确认名称和说明后才可运行。脚本由定时任务到点后在任务运行器里执行，用来完成这次更新。对话用来创建任务和提问，不在回答过程中执行脚本。未确认、不是 `.py`，或任务没有自己的代码时，任务运行器不运行，数据保持原样。
  - 同一次运行失败时，不把任务标成成功，当前可查询表数据保持运行前的版本；未发布候选可供重试。
  - 同一任务在已经成功的当天不重复运行。
  - 代码和 SOP 按任务绑定。不能把示例数据所用的更新代码用于另一项未指定的任务。
  - 任务可以绑定一个技能。技能上的代码标识不是任务自己的已指定代码；任务没有 `code_id` 时仍不运行。

### REQ-018 加工数据的血缘

- 触发：一次大模型加工或一次定时任务，把新的数据版本保存下来。
- 输入：本次实际读取的基础数据版本，本次加工步骤，以及实际执行的代码标识。基础数据至少要能指向文件、导入版本和数据版本。定时任务还要带上任务标识；用了技能时带上技能标识。
- 处理：
  - 一条已保存的加工数据版本对应一条血缘。重复保存同一次结果时覆盖同一条，不另建一条。
  - 加工步骤按顺序记下做了什么。步骤只描述加工，不保存代码正文、密钥、整表行或对话原文。
  - 定时任务必须记下所运行的 `code_id`。运行的是已发布代码版本时，同时记下该版本标识。
  - 大模型步骤没有登记代码时，代码标识为空，步骤中写明这是模型步骤。不能编造代码标识。
  - 运行时记下代码实际读到的表、文件和参数。模型根据这些输入对应基础数据版本。脚本正文里没有手写版本号，不阻止新版本可查询。某个输入对不上已登记版本时，血缘记下该输入并标明未对应，不编造版本号。
  - 定时任务成功后，模型根据这次实际读到的文件和所运行的代码，补上有顺序的加工步骤和一段描述。步骤和描述只说明加工，不保存代码正文、密钥、整表行或对话原文。模型补不上时，保留已经记下的输入文件和代码，并写明步骤或描述尚未生成，不编造。
  - 血缘写入 MongoDB 成功后，该加工版本才能成为可查询版本。写入失败时，当前可查询版本保持不变。
- 输出：按加工结果的数据版本可以取回基础数据、加工步骤和代码标识。没有记录，与 MongoDB 读取失败，使用不同说明。
- 约束：
  - 业务行仍在 PostgreSQL。血缘不进入文档 RAG，也不进入表数据工具。
  - 只读回答、未写回的查询结果、只生成字段说明或别名，都不写血缘。用户要求写回并成功保存的新版本，按本节记血缘。
  - 血缘一直保留，不因发布新版本、删除技能或再次导入而删除。全体用户可以按数据版本倒查，不按用户分开存放。
  - 失败且没有新数据版本时，不写一条成功血缘。任务失败仍按 REQ-017 记录。
  - 血缘不能代替回答中的来源，也不能用来补表里没有的数值。

### REQ-019 用户自建技能

技能是用户编写的一套工作方法，用来教模型完成一类工作。它至少包含名称、何时使用，以及要按顺序执行的步骤、检查项和输出要求。它不是一句回答口径。

- 触发：用户保存、修改或删除自己的技能；用户用 `@` 点名技能；或者本轮任务对上了某个技能。
- 输入：名称、何时使用、做法正文。做法里写清步骤。代码标识可空，只能是已登记标识，不能是代码正文、命令或路径。
- 处理：
  - 用户可以查看、新建、修改和删除技能。删除后，新的问题不能再点名它；已经写下的血缘标识保留，不改写成别的技能。
  - 显式指定有两种，效果相同：问题中用 `@` 加上已保存技能的名称；请求里已经带有该技能编号。现有技能选择与 `@` 都算显式指定。点名之后，模型按该技能的步骤完成本轮工作。
  - `@` 后按已保存名称做完整匹配，多个名称能对上同一段文字时取最长的名称。半角 `@` 与全角 `＠` 相同。
  - 本轮检索到的定时任务带有技能编号，且该技能仍存在、用户又没有另点技能时，模型按该技能的步骤处理。定时任务自己的脚本仍由任务运行器到点执行。
  - 没有 `@`、请求里没有技能编号、任务也没有技能编号时，用 BGE-M3 比较问题与技能的名称和“何时使用”。大于等于 0.9 且只有一个时，按该技能的步骤处理；大于等于 0.6 且小于 0.9，或同时有多个大于等于 0.9 时，请用户选择，选择前不检索；低于 0.6 不套用。等于 0.9 直接套用。内置技能不参与这路比较。
  - 用户已经显式指定技能时，只用该技能，不并入任务上的另一个技能。
  - 点名了多个技能、同一名称对应多个技能、`@` 与请求中的技能编号指向不同技能，或 `@` 对不上已保存技能：停下说明原因，不检索，也不套用别的技能。
  - 技能的步骤随本轮工作交给模型。用户的原问题保留，不把技能正文改写成用户说过的事实。
- 输出：指定成功时，模型按技能步骤完成这次工作，并仍进入原来的闲聊、简单查询或复杂任务路径。没有指定时，行为与未增加技能前相同。
- 约束：
  - 技能不能增加主 Agent 的动作，不能写长期记忆，也不能放宽 REQ-010、REQ-012 和 REQ-016。步骤与这些规则冲突时，按这些规则处理。技能可以要求把已经查到、字段对得上的结果写回；不能要求先编造数字再写回。
  - 技能可以指明定时任务使用哪段已确认脚本。脚本由任务运行器到点执行。技能上的代码标识单独存在时，不使一条没有自己代码的任务开始运行。
  - 内置技能不出现在用户的技能列表中，也不能靠 `@` 点名。任务若已保存某个内置技能编号，仍可按该编号找到做法。
  - 技能、元数据和表数据全体用户共享，不按用户分库。

### REQ-020 运行时限和已运行时间

- 触发：一次简单查询、一次复杂任务、一次结构化查询，或一次每日任务开始运行。
- 处理：从开始计时，上限 30 分钟。复杂任务里的子步骤共用这一次时限，不各自再计 30 分钟。对话页和任务列表在运行中显示已运行时间，结束后显示这次用了多久。
- 到达 30 分钟仍未结束：停止。查询只说明超时，不把未完成内容当成回答。定时任务记为失败，可查询版本保持运行前。
- 多条定时任务各自计时。某一任务把时间拖过另一任务的钟点时，被拖过的那次按错过处理，不补跑。

## 4. 业务边界

| 情形 | 结果 |
|---|---|
| 空问题、超长问题 | 拒绝进入检索，提示原因 |
| 闲聊 | 不查库、不联网 |
| 意图输出两次都无法解析 | 提示分类失败，不检索 |
| 分数等于 0.9 | 直接采用 |
| 分数在 0.6 与 0.9 之间 | 暂停，等待用户；不把第一名当成已确认 |
| 用户多选 | 每个选中名称各自检索同名资料块 |
| 用户否认唯一候选 | 不检索该名称 |
| 短名对应多个主体 | 询问用户，不默认取其中一家 |
| 问题中没有产品或主体名称 | 跳过名称索引，直接检索资料块，并与 HyDE、网页摘要一起 RRF |
| 子 Agent 中途需要确认 | 整次复杂任务暂停，确认后继续原任务 |
| 子任务已经有 4 个 | 不再派发第 5 个 |
| 已经补查两轮 | 停止补查，用已有证据回答 |
| 一个子任务已有两个追问 | Self-Ask 停止，交回已有证据和缺项 |
| 只有一方资料 | 回答已有部分，并写明缺口和来源 |
| 两条资料冲突 | 并列两处来源，不取平均，不选一个当成唯一事实 |
| 私有库失败、联网成功 | 说明私有库失败；联网内容单独标链接 |
| 联网失败、私有库成功 | 用私有库回答，附带私有库来源，并说明联网不可用 |
| 两者都没有资料 | REQ-010 的无资料说明 |
| 两者都调用失败 | 说明失败，不说成“知识库没有该资料” |
| 回答使用了网页内容但没有链接 | 该网页内容不能出现在最终回答里 |
| 用户说“记住这一点” | 写入长期记忆 |
| 用户只是在提问 | 不写入长期记忆 |
| 文件尚未登记元数据 | 不写入数据表，也不从表数据回答 |
| 入库字段与元数据不一致 | 拒绝本次入库，保留原有表数据 |
| 字段说明里有示例值，表中没有记录 | 说明没有数据，不把说明里的值当成记录 |
| 指标未确认，或公式是自由 SQL、跨表引用 | 说明缺少可用口径，不自行假定聚合 |
| 对维度、时间、主键或属性字段做 SUM 或 AVG | 拒绝该计算 |
| 表记录与文档对同一数字说法不同 | 已查出的表记录为准；表中无记录时，不用文档或字段说明里的数字填上 |
| 同一文件的原件、工作表和导入配置完全重复 | 不新建版本，不重新生成说明 |
| 新版本的值索引或元数据向量没有建好 | 继续查旧的可查询版本 |
| PDF、Word 或 Markdown | 只登记文件并走文档检索，不建业务表 |
| 两份文件没有登记关联 | 不自动连接，也不因对话中的确认而连接；只返回各自能确定的部分 |
| 结构化数据库连接失败 | 说明查询失败，不说成“没有数据” |
| 用户只是提问 | 不写回表 |
| 用户要求把本次已查到的结果写回表 | 字段一致时写新版本并记血缘；不在对话里执行脚本 |
| 定时任务未指定代码、脚本未确认或代码不存在 | 不运行，表数据不变 |
| 定时任务本次运行失败 | 状态为失败，表数据保持运行前的内容 |
| 同一任务当天已经成功 | 当天不再运行第二次 |
| 加工结果的脚本没有手写版本号 | 模型根据本次实际输入写血缘，新版本仍可查询；对不上的输入标明未对应 |
| 字段定义发生变化 | 由人处理迁移，不自动删列或填值 |
| 血缘写入失败 | 当前可查询版本不变 |
| 只产生对话回答或字段说明 | 不写血缘 |
| 按数据版本倒查血缘时 MongoDB 失败 | 说明读取失败，不编造基础数据或代码 |
| 问题中的 `@` 对不上已保存技能 | 说明未找到，不检索 |
| 点名多个技能，或同名技能不止一个 | 请用户选择，不合并做法 |
| 问题与技能相似度大于等于 0.9，且只有一个 | 套用该技能 |
| 相似度在 0.6 与 0.9 之间，或有多个达到 0.9 | 请用户选择，选择前不检索 |
| 相似度低于 0.6，且没有点名或任务绑定 | 不套用技能 |
| 错过计划时刻 | 不补跑 |
| 只追加一行业绩或同类业务行 | 表结构和字段定义不变；不改已有对话、文档向量和图；未开启值索引的列不重建索引 |
| 任务绑定了技能，用户又 `@` 了另一个 | 只按用户点名的技能处理 |
| 技能要求编造数字或承诺收益 | 仍按 REQ-010、REQ-012 和 REQ-016；不把编造的数字写回 |
| 任务没有自己的代码，只在技能上写了代码标识 | 任务不运行 |

## 5. 非功能需求

| 项 | 要求 |
|---|---|
| 准确与追溯 | 产品条款、财务数字、公告内容和网页结论都要回到所附来源 |
| 隔离 | 每个子任务使用自己的查询状态和输出目录，不能写乱另一个任务的检索结果 |
| 可观测 | 记录意图、ReAct 的判断、动作和观察、Self-Ask 追问、名称决策、检索状态和补查轮次。不记录密钥 |
| 性能阈值 | 单次简单查询、复杂任务、结构化查询、每日任务运行不超过 30 分钟。界面显示本次已运行时间 |
| 安全 | 不回答索取密钥、内部配置或原始检索块的请求；沿用现有拒绝口径。定时任务不接收任意命令。另附脚本只接受已确认的 `.py` |
| 结构化数据 | 元数据、表数据和技能全体用户共享，不按用户分库。值索引和元数据向量只用于召回；索引未完成时不切换可查询版本。文档检索所用的现有库保持不变 |
| 更新可观测 | 每次定时运行记录开始时间、结束时间、已运行时长、成功或失败、错误说明。不记录密钥和代码正文 |
| 血缘 | 可查询的加工版本必须有一条 MongoDB 血缘。记录一直保留，全体用户可倒查。记录不含密钥、代码正文和整表数据 |
| 技能 | 本轮实际使用的技能编号可追溯。技能正文不写入长期记忆 |

## 6. 验收标准

### AC-001 三类分流（REQ-002、REQ-003、REQ-004、REQ-007）

- 给定一句问候，且模型返回闲聊。预期：不出现名称确认、私有库检索或联网调用。
- 给定一个单主体资料问题，且模型返回简单查询。预期：走一次 REQ-004，主 Agent 不拆子任务。
- 给定模型返回复杂任务。预期：主 Agent 按 ReAct 派发子任务，用户最终只看到主 Agent 的回答。
- 给定分类接口未被调用。预期：不能完成分流。关键词命中不能代替这次 LLM 调用。

### AC-002 名称分数（REQ-005）

- 给定最高分大于 0.9。预期：直接采用，不询问。
- 给定最高分等于 0.9。预期：直接采用，不询问。
- 给定最高分在 0.6 与 0.9 之间，且有两个候选。预期：列出候选，允许多选；用户选择前没有正文检索。
- 给定最高分低于 0.6。预期：不把该命中当确认结果，转入注册表。
- 给定一个需求说明示例以外的产品名，分数规则相同。

### AC-003 最长匹配与歧义（REQ-006）

- 给定文本同时含有长规范名和它的短名。预期：长名占住对应文字，短名不重复截取。
- 给定一个未出现在示例里的简称，注册表中对应两个主体，上下文没有消解。预期：询问用户，不默认其中任何一个。

### AC-004 共用查询（REQ-004、REQ-008）

- 给定同一个已确认名称和同一个改写问题。操作：分别走简单查询和私有库子 Agent。预期：名称过滤、HyDE、百炼检索和三路 RRF 一致；子 Agent 不生成最终用户回答。
- 给定一个没有产品名的概念问题。预期：不查询名称索引，直接检索资料块。
- 给定普通检索、HyDE 和一条网页摘要。预期：三路进入同一次 RRF；摘要所在网页的链接留在结果里。
- 给定 HyDE 文本里出现一个资料中没有的数字。预期：该数字不进入回答事实。

### AC-005 失败、冲突、来源与上限（REQ-008、REQ-009、REQ-010）

- 给定私有库有资料、联网调用抛错。预期：回答使用私有库并附带来源，同时说明联网不可用。
- 给定检索组件连接失败。预期：提示失败，不用“未检索到足够信息”代替。
- 给定两份资料对同一事实给出不同数值。预期：两处都引用，不合并成一个数。
- 给定最终回答引用了网页摘要。预期：同一处附带该网页链接。没有链接时，这段摘要不出现。
- 给定已派发 4 个子任务且仍有缺口。预期：不派发第 5 个，回答写明缺口。
- 给定已经补查两轮。预期：不再开始第三轮补查。

### AC-006 合规、追问与长期记忆（REQ-012、REQ-013、REQ-014）

- 给定“我该不该现在买入这个产品”。预期：不给出买卖指令，保留风险提示和已有来源。
- 给定上一轮已确认主体后，用户用“它”追问赎回规则。预期：沿用该主体，不重新要求选择，除非出现新的歧义。
- 给定用户说“记住我只看稳健型产品”。预期：写入长期记忆，后续查询能读到。
- 给定用户只提问、没有要求记住。预期：不新增长期记忆。

### AC-007 两种框架（REQ-007、REQ-008）

- 给定一个复杂任务。预期：主 Agent 的记录里能看到判断、动作和观察；动作只来自 REQ-007 的四种。
- 给定私有库子任务需要一个中间问题。预期：子 Agent 用 Self-Ask 提出追问，并用共用查询取得证据；追问不超过两个。
- 给定联网子任务。预期：追问只调用百炼 MCP，证据含链接，不生成用户回答。

### AC-008 元数据与表数据（REQ-015、REQ-016）

- 给定一份示例文件以外的文件，元数据含表名、简介和两个字段说明，表中有对应记录。操作：业务人员按其中一个字段提出查找。预期：结果来自该表，来源包含来源文件名、表名和该字段；不读取无关示例文件的表。
- 给定一个 Excel，模型已草拟字段说明且程序推断了类型。操作：人员在入库时确认或修正类型、角色、说明、别名和 `value_index`。预期：确认前不发布本版表数据或值索引；发布后查询只使用确认后的字段定义和索引开关。
- 给定一项含 `COUNT(DISTINCT ...)` 的同表指标，且已确认。预期：按受限公式结构计算并处理零分母；给定自由 SQL、跨表公式或未确认指标，预期：拒绝执行并说明缺少可用口径。
- 给定指标只定义对金额的 `SUM`，问题另要求按区域过滤或按产品分组。预期：过滤和分组留在这次查询计划里，不把带 `WHERE` 或 `GROUP BY` 的自由文本当作公式执行。给定对属性字段求 `SUM`。预期：拒绝该计算。
- 给定字段说明中写有一个数值，但表中没有记录。预期：回答说明没有对应数据，不返回说明里的数值。
- 给定入库数据比元数据多一个字段。预期：本次不入库，原有记录保持不变。
- 给定两份已登记文件，元数据没有写明它们的关联。操作：需求要求把两份数据合成一个结果。预期：不自动连接。
- 给定结构化数据库无法连接。预期：提示查询失败，不用“没有对应数据”代替。
- 给定一个能由单表记录直接汇总的需求。预期：返回汇总结果和来源。给定一个还要依赖表外事实的需求。预期：只返回表中能够支持的部分，并说明缺口。
- 给定不同内容的文件再次导入。预期：旧原件、元数据和数据行仍可追溯，查询只命中新版；若 ES 或 Milvus 新索引失败，旧版继续可查。给定同一逻辑文件的原件字节、所选工作表和导入配置完全一致的重复上传，预期：不重新生成说明或数据版本，只清理本次重复的临时上传；明确修改元数据则另建版本。
- 给定 PDF、Word 或 Markdown。预期：登记 `doc_info` 并走文档 RAG，不自动建业务表或 ES 值索引。给定混合问题，预期：表工具和文档工具各返回来源，文档数字不覆盖真实表结果。

### AC-009 定时更新（REQ-017）

- 给定用户已经填写北京时间的钟点和 SOP，且任务绑定了可运行代码。预期：到点后由任务运行器执行这段代码，成功后左侧显示成功，目标表数据已更新。缺钟点、缺 SOP 或没有可运行代码时，这一条不运行。
- 给定另一项 SOP 和另一段指定代码。预期：运行的是这项任务自己的代码。
- 给定任务没有指定代码。预期：不运行，表数据不变。
- 给定指定代码运行中途失败。预期：状态为失败，当前可查询表数据仍是运行前的版本；未发布候选可供重试。
- 给定任务只是给基金业绩表追加一行，新行没有带来已开启值索引字段的新取值。预期：表结构不变，不重建值索引，不改写已有对话、文档向量和图。
- 给定更新让一个已开启值索引的字段出现新取值。预期：只补这个取值；补齐后才切换为可查询。索引失败则旧版仍可查询，任务不得标成功。
- 给定当天已经成功运行。预期：当天不会再次写入。
- 给定用户在对话里要求立即跑同一条定时任务的脚本。预期：对话回答过程不执行脚本。到了用户设定的北京时间，由任务运行器执行。

### AC-010 与原查询并存（REQ-004、REQ-016、REQ-017）

- 给定一个只涉及已入库文档、对不上任何文件表的问题。预期：仍走原有共用查询，不因为 PostgreSQL 没有对应表而拒绝回答。
- 给定一个表格结果被写成收益承诺。预期：沿用 REQ-012，不因数据来自 PostgreSQL 而放宽。

### AC-011 数据血缘（REQ-018）

- 给定定时任务成功写入一个新数据版本，且运行前读取了另一个已存在的数据版本。预期：MongoDB 中有一条血缘，能看到被读取的版本、加工步骤和所运行的 `code_id`；该版本成为可查询之前，这条记录已经写好。
- 给定同一次加工重复提交。预期：仍只有一条血缘，不出现第二条成功记录。
- 给定脚本正文没有写版本号，但这次运行实际读了已存在的 v1。预期：模型根据这次输入写下 v1，新版本可以查询。某个输入对不上已登记版本时，血缘标明未对应，不编造版本号。
- 给定定时任务已经成功，并且这次实际读了若干文件。预期：血缘列出这些输入文件和所运行的代码；加工步骤和描述由模型在任务成功后补上。模型没有补上时，仍能看到输入文件和代码，并说明步骤或描述尚未生成。
- 给定血缘库无法写入。预期：当前可查询版本保持加工前的内容。
- 给定一次只生成对话回答，或只生成字段说明。预期：不新增血缘。
- 给定一个示例文件以外的加工版本。预期：倒查规则相同，不引用示例文件的版本。
- 给定血缘读取失败。预期：说明读取失败，不返回编造的基础数据或代码名。

### AC-012 用户技能（REQ-019）

- 给定用户保存一份写有步骤的技能，例如先核对列、再追加一行、再根据本次读到的输入记下血缘。操作：用 `@` 点名它。预期：模型按这些步骤完成本轮工作，原问题仍在；来源、合规和表数据规则不放宽。
- 给定请求里带有该技能编号，问题中没有 `@`。预期：与 `@` 点名同一技能的效果相同。
- 给定 `@` 与请求中的技能编号指向两个不同的已保存技能。预期：请用户选择，不合并，不检索。
- 给定 `@` 对不上任何已保存技能。预期：说明未找到，不检索，不改用别的技能。
- 给定两个已保存技能，问题同时点名二者。预期：请用户选择，不合并两份做法，不检索。
- 给定一个已绑定技能的定时任务被本轮检索到，用户没有另点技能。预期：模型按任务绑定的技能处理。
- 给定任务绑定技能甲，用户 `@` 技能乙。预期：只按技能乙处理。
- 给定问题措辞与某技能的名称或说明相似，且没有 `@`、没有技能编号，任务也没有绑定。相似度大于等于 0.9 且只有一个时，预期：套用该技能。相似度在 0.6 与 0.9 之间，或有多个达到 0.9 时，预期：请用户选择，选择前不检索。低于 0.6 时，预期：不套用。
- 给定技能要求把表中没有的数字写进回答或写回表。预期：拒绝该数字，不写回。
- 给定用户要求把刚查到、且与已确认字段一致的结果写回。预期：写入新版本，血缘成功后才可查询；对话不执行脚本。
- 给定任务自身没有代码，技能上写有代码标识。预期：任务不运行，表数据不变。

### AC-013 已确认的运行、任务和共享规则（REQ-016、REQ-017、REQ-018、REQ-020）

- 给定一次查询或一条每日任务已运行 30 分钟仍未结束。预期：停止并说明超时；任务不把新版本标成可查询。运行过程中界面能看到已运行时间，结束后能看到这次用了多久。
- 给定任务的计划时刻已经错过，进程当时没有跑到它。预期：不补跑。
- 给定两条任务都处于启用，且钟点已经确认。预期：两条都可以到点运行。停用其中一条后，只有被停用的那条不再自动运行，表数据不变。
- 给定用户另附一段 `.py`，但名称和说明尚未确认。预期：任务不运行。确认后，任务运行的是这段已确认脚本，而不是另一条任务的代码。
- 给定任意两名用户。预期：他们看到同一份元数据、表数据、技能和血缘；血缘记录不被新版本或删除技能清掉。

| OPEN-020 | 任务代码可以是已登记函数，或另附并经人员确认名称和说明的 `.py`。未确认脚本不运行 |
| OPEN-021 | 文件与主键、文件与文件的关联必须由导入人员明示确认。没有写下的关联不查询，不另造业务主键 |
| OPEN-022 | 用户要求时，可以把本次已查到且字段一致的结果写回已登记表。只读提问不写回。写回前先完成血缘 |
| OPEN-023 | 元数据、表数据、技能和血缘全体用户共享，不按用户分库 |
| OPEN-024 | 血缘一直保留。全体用户可以按数据版本倒查 |

每个子任务最多两个 Self-Ask 追问，是为了让 REQ-007 的停止条件在子 Agent 内部同样生效。
